# Resource packs

Server resource packs for the Gameplay Platform. One folder per theme (`muur/` now, others later); each builds to its own zip and gets its own stable pack id on the platform.

## Layout

```
resourcepacks/
  muur/                 pack source (what ends up in the zip)
    pack.mcmeta         pack_format 97 = client 26.3 (version.json pack_version.resource_major)
    assets/muur/
      equipment/        armour layer definitions (asset ids muur:collar, muur:paws)
      textures/entity/equipment/humanoid/   64x32 worn layers: <name>.png (tinted by dye) + <name>_overlay.png (never tinted)
      textures/item/    inventory icons (<name>_fur + <name>_pink) and parts.png (swatches for the 3D models)
      models/item/      *_icon (flat) and *_3d (cuboid models: ears_3d for the head slot, tail_3d for item_display)
      items/            item definitions: muur:ears (3D model only in the `head` display context), muur:collar, muur:paws, muur:tail, muur:tail_3d
  tools/
    gen_muur.py         one-off bootstrap of the muur assets (OVERWRITES; do not run over hand-edited art)
    build.py            validate + reproducible zip + SHA-1:  python tools/build.py muur
    preview.py          static previews into preview/ (armour layers, icons, isometric model renders)
    render_player.py    textured preview of a player wearing the kit (needs tools/ref/steve.png, copied from the 26.3 client jar, git-ignored)
  dist/                 build output (muur.zip, muur.json)
  preview/              generated previews, not part of the pack
```

## Colour

Fur is near-white and is tinted by the item's `minecraft:dyed_color` (worn layer, inventory icon and 3D model alike);
pink details are separate untinted layers. Undyed = white fur with pink details.

## Using it

1. `python tools/build.py muur`
2. Host `dist/muur.zip` at a direct https URL (GitHub release asset works).
3. Generate the push definition: `PACK_URL=<url> python ../mechanics/muur/gen_pack_push.py` (it ships disabled, see `mechanics/muur/README.md`).
   Any change to the pack changes the SHA-1; regenerate the definition after every rebuild.

## Item ids used by mechanics

| Item | `minecraft:item_model` | worn layer (`equippable.asset_id`) | how it is drawn |
|---|---|---|---|
| ears (head) | `muur:ears` | none | the client renders the head-slot item itself: `ears_3d` with `display.head` (rotation 0, scale 1.6) |
| collar (chest) | `muur:collar` | `muur:collar` | armour layer; the bell is painted on it (2x2 pixels) |
| tail (legs) | `muur:tail` | none | one follower `item_display` with `muur:tail_3d` (see the mechanic) |
| paws (feet) | `muur:paws` | `muur:paws` | armour layer |

3D models use 1 unit = 1 player-model pixel, model centre (8, 8, 8) = anchor, front = -Z. Confirmed on a real 26.3 client:
head-slot ears need rotation [0, 0, 0] and scale 1.6; the tail display needs NO extra 180 degree flip.
Textures are generated by `gen_muur.py` (clean pixel art, not hand-drawn); repaint them by hand and stop re-running the generator.
